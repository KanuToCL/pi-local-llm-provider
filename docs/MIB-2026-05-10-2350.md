## 3. NEW SECONDARY finding — cwd-vs-Desktop gap

Sergio's prompt said "Create it in desktop." Pi-mono's cwd is
hardcoded to `piCommsWorkspace`:

```typescript
// src/session.ts:473
cwd: this.opts.config.piCommsWorkspace,
```

(which resolves to `~/.pi-comms/workspace/`).

If the model HAD emitted `write_file("index.html", ...)`, the
file would have landed in `~/.pi-comms/workspace/index.html`, not
`~/Desktop/index.html`. To honor "Create it in desktop", the
model would have needed to:

1. Emit absolute paths (`/home/kanuto/Desktop/cars-explained/index.html`), AND
2. Have an active /unsand to write outside the sandbox root.

Audit shows `/unsand scope=next-task` was active at 23:00:13 for
the task that ran at 23:00:35, then disabled per the
`unsand_disabled reason=task_completed` row. By the time
`T-78c1cd526b2f` started at 23:03:18, /unsand was off. So even
a well-behaved model emitting absolute paths would have been
blocked by the sandbox.

**This is a separate UX gap from the model-lying problem.** Two
different fixes:

3a. **Surface the cwd-vs-user-intent contradiction to the user.**
   When the user message contains a path token outside the
   workspace AND the model is about to operate, the daemon could
   inject a system_notice: "you asked me to create files in
   `~/Desktop/`, but my tools operate from `~/.pi-comms/workspace/`.
   Reply `/unsand` then re-send to widen access, or I'll work in
   the workspace and you can move files after." Cheap heuristic;
   prevents the silent-mismatch pattern.

3b. **Document the cwd discipline in the user-facing prompt.** The
   prompt currently does not tell the user where files land. If
   you're remote (Telegram), you have no way to know without
   running `ls ~/.pi-comms/workspace/` from a separate session.
   At minimum, the `task_completed` outbound formatter should
   append a "(workspace: ~/.pi-comms/workspace/)" footer when
   files were written and the user message mentioned a path
   outside the workspace.

Neither 3a nor 3b changes the model-lying root cause; they
address the orthogonal "even if the model worked, output went to
the wrong place" problem.

**Ask 3 (new):** approve 3a as a v0.3.2-class addition? 3b is a
trivial outbound-formatter tweak; ship under the same followup.
