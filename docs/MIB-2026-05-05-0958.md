## 3. Architecture summary (what shipped)

### F1+F2 (poll-attempt heartbeat) — `src/channels/poll-attempt-transformer.ts` (NEW)

```typescript
bot.api.config.use(async (prev, method, payload, signal) => {
  const result = await prev(method, payload, signal);
  if (method === "getUpdates" && result.ok) {
    try { onPollAttempt(); } catch { /* never break loop */ }
  }
  return result;
});
```

Plus a `Symbol.for(...)` 2x-install guard. Empty `getUpdates` returns now touch heartbeat — F2 false-positive root cause GONE.

### F1 layer 2 (self-healing watchdog) — `src/daemon.ts` `TelegramPollWatchdog`

5 defenses (in order at `checkLiveness` tick):
1. **Cooldown gate** — after 3 consecutive restart failures, suppresses for 10min (Adversarial B3 + PE B1)
2. **`restartInFlight` guard** — never fire restart while previous in flight
3. **`isConnected()` gate**
4. **`shuttingDown` CAS flag** (PE B2)
5. **Monotonic-clock age check** (`process.hrtime.bigint()` — immune to suspended-laptop wall-clock jumps per Adversarial I5)

On stale: `restart("poll_silent_too_long")` — full Bot reconstruction via `botFactory()` + re-installs middleware + re-installs Transformer + `bot.api.getMe()` re-probe. Addresses Adversarial B2 (outbound TCP shared with inbound — fresh Bot = fresh API = fresh node-fetch agent).

**Hard timeout** (FIX-W4 IMPORTANT-1): `Promise.race([restartP, timeoutP])` with hard timeout = 2× staleMs. If `bot.stop()` or `bot.api.getMe()` hangs, the timeout fires + counter increments + `restartInFlight` clears + watchdog re-fires next tick.

**Operator-log payload**: synchronous emit has `age_ms` + `threshold_ms` (NOT empty json — that was FIX-W5). Forensic enrichment fires fire-and-forget post-decision via `telegram_poll_stale_restart_full_snapshot` line with full `heartbeat_ages_json`.

### F3-A (system prompt OS hint) — `prompts/coding-agent.v3.txt` + `composeSystemPrompt`

Bumped v2→v3 with conditional `${HOST_ENV_SECTION}` placeholder:
- **win32** → full caveat block: `mkdir -p X` → `mkdir X`, `cat F` → `type F`, `rm -rf X` → `rmdir /s /q X` (for dirs) or `del /f /q X` (for files), backslash paths.

`ALLOWED_HOST_OS` whitelist (8 platforms) + post-substitution scan throws if `${HOST_ENV_SECTION}` or `${HOST_OS}` survives — defense-in-depth against prompt injection (Security W1).

**Note**: F3-B (cmd-rewriter) was DROPPED entirely per Adversarial B4/B5 — `mkdir -p X && cd Y` would have silently corrupted via shell-metachar handling, `rm -rf foo.txt` → `rmdir /s /q foo.txt` would have failed. F3-A prompt-only is sufficient — the model self-corrects from cmd.exe errors.

## 6. Known limitations + caveats

1. **Worst-case time-to-recovery from hung restart**: ~390s (= staleMs 120s + hardTimeout 240s + tickMs 30s) before the FIRST retry; cooldown engages after 3 such cycles ≈ 19.5min then a 10-min cooldown. Acceptable for single-user pi-comms with operator-on-phone semantics.

2. **`telegram_poll_stale_restart` synchronous emit has only `age_ms` + `threshold_ms`** (no full ages). Full snapshot lands in the deferred `_full_snapshot` line. Operators correlate via timestamp + age_ms. Documented in playbook §3.

3. **Outbound `sendMessage` orphan during restart**: best-effort logged via `telegram_send_error`. Multi-chunk replies can fragment silently mid-restart (chunk 1 succeeds, chunk 2 hits dead bot.api). Rare path. Tracked v0.4.

4. **Audit forward-compat is one-way for now**: v0.3 audit logs CAN be parsed by v0.2.2 daemons (per the schema relaxation). v0.2.2 audit logs are bidirectionally fine.

5. **`prompts/coding-agent.v2.txt` preserved** as fallback fixture + config-rollback path. If v3 prompt regresses agent behavior, set `basePromptPath` config back to v2.
